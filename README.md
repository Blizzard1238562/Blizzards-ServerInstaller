# Blizzards Server Installer

### This Project is Vastly Vibe-Coded and was first meant only for personal use.

An interactive installer that sets up a Minecraft server. You pick the server
software (Paper, Purpur, Pufferfish or Folia) and Minecraft version, choose
plugins, and answer a few yes/no questions about gameplay settings. It then
downloads the server jar and plugins, patches the server config to match your
answers, and writes the start scripts.

What it does:

- Downloads the server jar from mcjars.app, with a fallback to PaperMC's own
  API for Paper.
- Fetches the newest compatible build of each chosen plugin from Modrinth and
  adds required dependencies automatically (WorldEdit for WorldGuard, Geyser
  for Floodgate, etc.).
- Offers two modes: **Quick start** (latest Paper + a small essentials set -
  TAB, ViaVersion, SimpleTPA - asks only for the server name, folder and RAM)
  and the original **Full setup** wizard that customizes everything (server
  seed, gamemode, spawn protection, Nether, command blocks and more). On
  Folia, Full setup only offers plugins whose authors ship Folia-compatible
  builds.
- The RAM question is prefilled from your machine's total memory (half of it,
  capped at 8 GB, never below 1 GB) in both modes - press Enter to accept it
  or type your own amount.
- On startup, quietly checks GitHub Releases for a newer installer version
  and prints a hint when one exists (offline installs are unaffected).
- Asks for a server name (or lets you hit Enter for a default). When TAB is
  installed, the name is shown at the top of the tablist in Minecraft "small
  font" (Unicode small caps, e.g. ᴍʏ ꜱᴇʀᴠᴇʀ) in a color of your choice.
- Starts the server once so Paper generates its own default config files, then
  patches only the settings you answered for. This is safer than writing a
  full paper-global.yml by hand, since the config schema changes between
  Minecraft versions.
- Writes `eula.txt`, `server.properties`, and `start.bat` / `start.sh` with
  Aikar's flags and the RAM you chose, plus `stop`, `restart` and `backup`
  helper scripts (stop/restart target only this server's java process;
  backup archives the worlds + plugins into `backups/` with a timestamp).
- Re-running the installer into a server folder it created offers to update
  that server (newest jar and plugin builds) instead of installing a fresh
  copy - worlds, configs and start scripts are kept as they are.
- If Java is not on PATH, the install still completes and writes a
  `MANUAL_CONFIG_NOTES.txt` listing the settings to change by hand.

## Running it

**Option 1: with Python** (Windows, Linux, Mac). Nothing to build:

```
run.bat        # Windows
./run.sh       # Linux / Mac
```

Both scripts install `PyYAML` if it is missing, then start the wizard (HTTP
uses Python's standard library, so no other runtime dependencies are needed).

Headless / scripted installs use the same entry point with flags (any flag
switches to an unattended Quick start):

```
installer.py --quick --dir ./server --name "My Server" --ram 4096
```

`--dir` defaults to `./server`, `--name` to `Minecraft Server`, and `--ram`
to the auto-detected suggestion. The install never prompts; an unreachable
version list fails with a non-zero exit code, as does a non-empty folder the
installer did not create. Point `--dir` at a folder the installer *did*
create and it refreshes that server instead (newest jar + plugins, configs
kept).

**Option 2: standalone .exe** (no Python needed on the target machine).
Download it from the [latest release](https://github.com/Blizzard1238562/Blizzards-ServerInstaller/releases/latest),
or build it yourself. PyInstaller does not cross-compile, so the exe has to be
built on a Windows machine:

```
pip install -r requirements.txt
build_exe.bat          # produces dist\Blizzards-Server-Installer.exe
```

Requirements: Python 3.9+ to run from source. Java 21+ on PATH is only needed
for the automatic config generation step.

## What you end up with

A server folder containing:

- the server jar (`paper-1.21.4.jar` or the equivalent for the chosen software)
- `eula.txt`, already set to `true`
- `server.properties` with your MOTD, difficulty, PvP, whitelist and the rest
  (plus `whitelist.json` and/or `ops.json` for the players you whitelisted or
  made operators - UUIDs resolved automatically, including offline-mode
  UUIDs)
- `config/paper-global.yml` and `config/paper-world-defaults.yml`, generated by
  Paper and patched (the `unsupported-settings` toggles and anti-xray)
- `plugins/` with the plugins you chose. TAB gets a real, minimal `config.yml`
  whose tablist header shows your server name in small caps with an online
  player count; SimpleTPA and SimpleHomes get pinned default configs (byte-
  exact copies of what the plugin ships, so behavior can't drift when the
  plugin updates)
- `start.bat` / `start.sh` (Aikar's flags) plus `stop`, `restart` and
  `backup` helper scripts
- `blizzards-installer.json` - a small manifest recording the install, used
  when you re-run the installer to update this server later
- `MANUAL_CONFIG_NOTES.txt`, only when Java was not found

## Releases

Pushing a tag that starts with `v` builds the exe on GitHub Actions and creates
a GitHub release with the exe attached:

```
git tag v1.1.0
git push origin v1.1.0
```

Pushes to `main` and pull requests run the unit tests and build the exe as an
artifact, without creating a release.

## Project layout

```
installer.py                # entry point: dependency checks + error handling
blizzards_installer/        # the actual code, split by concern
    wizard.py               #   the interactive question flow (run_wizard)
    serverjar.py            #   SERVER_TYPES registry + server jar downloads
    plugins.py              #   plugin registry loading + Modrinth downloads
    config.py               #   server.properties/eula + Paper config bootstrap/patching
    net.py / versions.py    #   HTTP/downloads, Mojang version list
    ui.py / scripts.py      #   console prompts, start.bat/start.sh
    meta.py                 #   version + User-Agent
plugins.json                # plugin list and questions. Add plugins here, not in code
test_installer.py           # smoke/integration tests (python test_installer.py)
```

## Extending

**Server software.** Add an entry to `SERVER_TYPES` in
`blizzards_installer/serverjar.py`. The jar download, plugin download and
question flow are generic over this dict. The config patching assumes Paper's
config layout (`config/paper-global.yml` with `unsupported-settings`), so
structurally different software such as Vanilla or Spigot would need extra
handling there.

**Plugins.** Add an entry to `plugins.json`. Each entry needs a Modrinth slug,
a question, a default answer, and optionally a list of required plugin ids.
Existing dependencies: Floodgate requires Geyser, WorldGuard requires
WorldEdit.

## Development

```
python test_installer.py
```

The test suite does not touch the network. It feeds fixture data through the
parsing and patching functions, and drives the full wizard with only the
network calls mocked.

## Roadmap

Shipped:

- **Public servers.** After an install, expose the server so players can join
  through a friendly playit.gg address instead of a raw `IP:port`, no port
  forwarding or public IP needed. Design and service evaluation live in
  [docs/public-servers.md](docs/public-servers.md).
- **Plugin config presets.** TAB gets a minimal small-font tablist config;
  SimpleTPA and SimpleHomes get pinned default configs so a fresh server
  works without manual setup.
- **Quick start mode.** One screen to a working server with the essentials.
- **Folia-aware plugin list.** Full setup offers only Folia-compatible plugins
  when Folia is the server software, instead of a blanket warning.
- **Installer self-update check.** A startup hint when a newer release exists.
- **Sensible RAM default.** The RAM question is prefilled from detected system
  memory (half, capped at 8 GB, min 1 GB) in both modes.
- **More Full-setup options.** World seed, gamemode, spawn protection, Nether,
  End and command blocks.
- **Initial operators and whitelist names.** Full setup asks for the players
  to whitelist and/or make operators; their real (or offline-mode) UUIDs are
  resolved automatically so the entries actually match on join.
- **Unattended CLI flags.** `--quick`, `--dir`, `--name`, `--ram` for
  scripted or headless installs.
- **Management scripts.** `stop`/`restart`/`backup` next to the start
  scripts (target only the server's own java process; backups land in
  `backups/`).
- **Re-run to update.** Running the installer into an existing server folder
  refreshes the jar and plugins while keeping worlds and configs - both in
  the wizard's Update mode and via the CLI `--dir`.

## Known limitations

- mcjars.app does not document its response format, so the jar lookup scans
  responses for a `.jar` URL instead of relying on a fixed field path. If the
  format changes, Paper installs fall back to the PaperMC API automatically;
  Purpur, Pufferfish and Folia depend on mcjars being reachable.
- Config patching targets the 1.19+ `config/` folder layout, with best-effort
  support for the older single-file `paper.yml`.
- The plugin list is written for Paper, Purpur and Pufferfish. On Folia, most
  plugins will not load unless the author added Folia support.
