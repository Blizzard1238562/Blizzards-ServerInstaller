# Blizzards Server Installer

An interactive installer that sets up a Minecraft server. You pick the server
software (Paper, Purpur, Pufferfish or Folia) and Minecraft version, choose
plugins, and answer a few yes/no questions about gameplay settings. It then
downloads the server jar and plugins, patches the server config to match your
answers, and writes the start scripts.

What it does:

- Downloads the server jar from mcjars.app, with a fallback to PaperMC's own
  API for Paper.
- Fetches the newest compatible build of each chosen plugin from Modrinth and
  adds required dependencies automatically (Vault for EssentialsX, WorldEdit
  for WorldGuard, etc.).
- Starts the server once so Paper generates its own default config files, then
  patches only the settings you answered for. This is safer than writing a
  full paper-global.yml by hand, since the config schema changes between
  Minecraft versions.
- Writes `eula.txt`, `server.properties`, and `start.bat` / `start.sh` with
  Aikar's flags and the RAM you chose.
- If Java is not on PATH, the install still completes and writes a
  `MANUAL_CONFIG_NOTES.txt` listing the settings to change by hand.

## Running it

**Option 1: with Python** (Windows, Linux, Mac). Nothing to build:

```
run.bat        # Windows
./run.sh       # Linux / Mac
```

Both scripts install `requests` and `ruamel.yaml` if they are missing, then
start the wizard.

**Option 2: standalone .exe** (no Python needed on the target machine).
Download it from the [latest release](https://github.com/Blizzard1238562/Blizzards-ServerInstaller/releases/latest),
or build it yourself. PyInstaller does not cross-compile, so the exe has to be
built on a Windows machine:

```
pip install -r requirements.txt
build_exe.bat          # produces dist\Blizzards-Server-Installer.exe
```

Requirements: Python 3.9+ to run from source. Java 21+ on PATH is only needed
for the automatic config generation step.

## What you end up with

A server folder containing:

- the server jar (`paper-1.21.4.jar` or the equivalent for the chosen software)
- `eula.txt`, already set to `true`
- `server.properties` with your MOTD, difficulty, PvP, whitelist and the rest
- `config/paper-global.yml` and `config/paper-world-defaults.yml`, generated by
  Paper and patched (the `unsupported-settings` toggles and anti-xray)
- `plugins/` with the plugins you chose. TAB gets a placeholder `config.yml`
  for now, see the roadmap
- `start.bat` and `start.sh` with Aikar's flags
- `MANUAL_CONFIG_NOTES.txt`, only when Java was not found

## Releases

Pushing a tag that starts with `v` builds the exe on GitHub Actions and creates
a GitHub release with the exe attached:

```
git tag v1.1.0
git push origin v1.1.0
```

Pushes to `main` and pull requests run the unit tests and build the exe as an
artifact, without creating a release.

## Project layout

```
installer.py                # entry point: dependency checks + error handling
blizzards_installer/        # the actual code, split by concern
    wizard.py               #   the interactive question flow (run_wizard)
    serverjar.py            #   SERVER_TYPES registry + server jar downloads
    plugins.py              #   plugin registry loading + Modrinth downloads
    config.py               #   server.properties/eula + Paper config bootstrap/patching
    net.py / versions.py    #   HTTP/downloads, Mojang version list
    ui.py / scripts.py      #   console prompts, start.bat/start.sh
    meta.py                 #   version + User-Agent
plugins.json                # plugin list and questions. Add plugins here, not in code
test_installer.py           # smoke/integration tests (python test_installer.py)
```

## Extending

**Server software.** Add an entry to `SERVER_TYPES` in
`blizzards_installer/serverjar.py`. The jar download, plugin download and
question flow are generic over this dict. The config patching assumes Paper's
config layout (`config/paper-global.yml` with `unsupported-settings`), so
structurally different software such as Vanilla or Spigot would need extra
handling there.

**Plugins.** Add an entry to `plugins.json`. Each entry needs a Modrinth slug,
a question, a default answer, and optionally a list of required plugin ids.
Existing dependencies: Floodgate requires Geyser, EssentialsX requires Vault,
WorldGuard requires WorldEdit.

## Development

```
python test_installer.py
```

The test suite does not touch the network. It feeds fixture data through the
parsing and patching functions, and drives the full wizard with only the
network calls mocked.

## Roadmap

Next up:

- **Public servers.** After an install, expose the server so players can join
  through a friendly playit.gg address instead of a raw `IP:port`, no port
  forwarding or public IP needed. Design and service evaluation live in
  [docs/public-servers.md](docs/public-servers.md).
- **Config presets for plugins.** Ship real default configs for the offered
  plugins, starting with TAB (which currently only gets a placeholder), so a
  fresh server works without manual setup.

Later:

- Support for more server software (Vanilla, Spigot) with config patching for
  their layouts.
- Folia-aware plugin list: filter plugins by the chosen server software instead
  of warning that most plugins will not run on Folia.
- A simple GUI around the wizard.

Ideas:

- Auto-update for the installer itself, checking the GitHub releases for a
  newer version.
- Management scripts next to `start.bat` / `start.sh`: stop/restart, world
  backups, crash auto-restart.
- Show a preview of the config changes before the install runs.

## Known limitations

- mcjars.app does not document its response format, so the jar lookup scans
  responses for a `.jar` URL instead of relying on a fixed field path. If the
  format changes, Paper installs fall back to the PaperMC API automatically;
  Purpur, Pufferfish and Folia depend on mcjars being reachable.
- Config patching targets the 1.19+ `config/` folder layout, with best-effort
  support for the older single-file `paper.yml`.
- The plugin list is written for Paper, Purpur and Pufferfish. On Folia, most
  plugins will not load unless the author added Folia support.
